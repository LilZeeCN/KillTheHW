# KillTheHW：工科实验报告自动化与审计引擎

终结实验报告中的形式主义与排版内耗。把学生从找要求、调字体、截几十张图、对号入座贴图的琐碎劳动中解放出来。默认简体中文；作业要求的语言、学校模板版式与评分标准绝对优先。

本 Skill 由当前 Agent 执行：Python 脚本负责底层模板 XML 精准注入、环境检测与账本校验；推理、电脑操作 (CU)、上下文理解与语义核验由宿主 Agent 完成。

---

## 三大核心工作流路由

根据用户当前提供的材料完备程度，自动匹配最适合的执行路径：

```
┌────────────────────────────────────────────────────────────────────────┐
│                          KillTheHW 执行路由                            │
└────────────────────────────────────────────────────────────────────────┘
  ├── 模式 1【整理与保版】: 已有数据/截图/日志 ──► 匹配小节与模板 ──► 生成 DOCX
  ├── 模式 2【运行与取证】: 有指导书与代码项目 ──► PTY/CU操作取证 ──► 组装报告
  └── 模式 3【预检与审计】: 已有报告草稿 ──────► 对照评分点查漏 ──► 输出审计单
```

1. **模式 1：整理与保版装配（Format & Assemble）**
   - **适用**：用户已跑完实验，拥有代码、日志、表格或分散的截图，需要套用学校 DOCX 模板。
   - **执行**：读取学校模板与散落材料，提取模板结构清单，自动排版正文、插入图文并绑定中西文字体规范，生成无损保版的可编辑报告。
2. **模式 2：全流程运行与取证（Run & Evidence Capture）**
   - **适用**：用户提供实验指导书、可运行代码/脚本或指定运行环境，需要代跑并取证。
   - **执行**：根据指导书解析必做题目与评分要求；终端命令优先在持久 PTY 会话中运行并保留原始日志快照，GUI 界面通过宿主 CU 操作并捕获真实截图；将证据链严格按题号回填至报告模板。
3. **模式 3：报告预检与审计（Audit & Rubric Check）**
   - **适用**：用户已有写好的报告，需要审查是否满足老师要求。
   - **执行**：提取指导书中的评分细则、小问清单与格式约束（如字数下限、必答思考题），运行审计比对，输出《实验报告交付预检审计单》，标明遗漏点与风险项。

## 执行规范与阶段推进

### 阶段一：材料解析与环境初检
1. **环境检测**：初次启动或排障时，可执行 `scripts/check_env.py` 探查当前系统的 Python 库、文档处理引擎、PTY 终端与宿主 CU 能力。
2. **建档与提取**：
   - 提取材料范围，使用 `scripts/inspect_inputs.py --job-dir <工作目录> <材料路径...>` 初始化账本。只扫描用户提供的路径，不越界遍历整机。
   - 执行 `scripts/extract_materials.py <工作目录>` 初步解析 PDF、DOCX、PPTX 等材料文本与内嵌媒体。
3. **要求与格式提取**：
   - 提取实际布置的题目、小节、选做组，并显式记录**格式规范**（例如：封面字段、正文字体/字号、行距、思考题字数要求）。
   - 将要求注册进 `job.json`（可参考 [任务记录](references/job-record.md) 与 `scripts/register_requirements.py`）。

### 阶段二：操作执行与证据沉淀
1. **真实环境操作**：
   - 命令行、数据库与脚本任务优先按 [终端与证据](references/terminal-evidence.md) 使用持久 PTY，保留退出状态与完整日志；
   - 浏览器与桌面软件任务按 [电脑操作](references/computer-use.md) 使用宿主 CU 工具执行，捕捉真实界面窗口。
2. **截图规范与对号入座**：
   - 每张截图必须严格对齐对应题号与要求 ID。截图内容保留清晰的技术上下文（如命令提示符、查询结果表格），避免无关大面积留白。
   - 终端日志渲染图仅在无法直接截图时使用，且必须标注来源说明。

### 阶段三：模板填充与去 AI 化写作
1. **模板保版填充**：
   - 阅读 [模板填充](references/report-template.md)。使用 `scripts/build_report.py inspect <模板.docx> --out template-map.json` 解析原始锚点与段落。
   - 编写填充计划，调用 `scripts/build_report.py build` 构建报告。自动继承原模板样式，支持精确设置中文字体（如宋体）、西文字体（如 Times New Roman/Courier New）、字号、行距与图文对齐。
2. **去 AI 化表达审阅**：
   - 严格遵循 [写作风格](references/writing-style.md)。以本次真实运行的参数、步骤和客观数据为核心依据。
   - **保留真实调试痕迹**：在心得或排错部分真实记录遇到的环境或代码问题及解决办法，体现真实动手过程。
   - **剔除 AI 套话**：删除一切空洞宏大的背景叙事、刻板的“首先/其次/最后”和虚假感悟；详略跟随实际技术信息量。

### 阶段四：预检审计与交付
1. **运行预检审计**：
   - 执行 `python3 <skill>/scripts/check_deliverables.py <工作目录> --summary` 生成结构化预检单。
   - 确认所有必做要求、题目、截图证据与交付物版本完全绑定。
2. **页面与视觉检查**：
   - 阅读 [交付与核验](references/delivery.md)。检查生成的 DOCX 打开是否正常，确认封面无下划线缺失、表格未变形、图片未溢出页面。
3. **交付输出**：
   - 最终交付可直接编辑打印的 DOCX 报告、已验证的证据链清单以及《实验报告交付预检审计单》。

## 随包工具箱

- `check_env.py`：检测本地环境与依赖（python-docx, Pillow, pyte, pdftotext, LibreOffice, PTY），给出支持模式与修复建议。
- `inspect_inputs.py`：创建任务目录，建立材料散列与类型账本，杜绝覆盖已有任务。
- `extract_materials.py`：深度提取 PDF/DOCX/PPTX 等材料文本与媒体附件。
- `register_requirements.py`：从题目与指导书中解析候选清单并分配关联 ID。
- `build_report.py`：检查 DOCX 模板结构，在指定锚点注入文字、代码、截图与图注，原生支持中西文字体、字号与段落排版。
- `pty_session.py` / `render_terminal.py`：管理持久 PTY 会话，自动托管 caffeinate 防休眠断言，生成高保真真实终端日志渲染图。
- `capture_window.py`：基于 macOS CoreGraphics 与 WindowID 的后台静默窗口截取工具，免切前台、不抢焦点、无阴影输出。
- `crop_content.py`：截图智能边缘裁剪辅助工具。
- `check_deliverables.py`：检查要求覆盖率、文件版本一致性与实质核验记录；支持 `--summary` 输出人类可读的预检审计单。
- 更多后台静默运行与虚拟显示器配置，请参考 [macOS 静默执行指南](references/headless-macos-guide.md)。
