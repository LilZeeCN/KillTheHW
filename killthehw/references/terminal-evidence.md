# 终端任务与锁屏取证

## 选择执行通道

命令行、SQL、Hadoop/Hive/HBase、编译和数据处理优先用宿主终端工具或独立 PTY；已有合适 tmux 会话时可以复用，不必向 GUI 终端逐字输入。CU 处理浏览器、桌面软件及题目确实要求的界面步骤。选择依据是任务需要，不是所有作业都必须模拟键盘操作。

长任务用持久会话。随包 pty_session.py 在 POSIX 系统上提供独立后台 PTY，无需 tmux；不支持 Windows 原生控制台时用宿主终端或 WSL。会话在 Agent 单次调用结束后继续运行，但不保证机器睡眠、关机、SSH 断开或宿主进程管理后的存活。远程长任务优先在目标机器的 tmux 等可恢复会话中运行，并在本地账本记录入口。

## 一个任务一个明确的命令入口

```bash
python3 <skill>/scripts/pty_session.py start /任务目录 lab1-query --cwd /代码目录 -- /bin/bash /代码目录/run-query.sh
python3 <skill>/scripts/pty_session.py status /任务目录 lab1-query --wait 20
```

命令通过 `--` 后的 argv 传递，不隐式拼接 shell。复杂操作放进可审阅的脚本，指定 shell 执行；多步脚本显式传递失败状态。每个会话独立，避免未退出的 MySQL/HBase 客户端把后续系统命令当成自身输入。

status 的 state 为 starting/running/exited/stopped/interrupted；只有 exited 且 exit_code=0 表示命令正常退出，仍需核查业务结果。查询等待超时返回 running，不自动杀进程，也不标为完成。等待最多 60 秒，长任务分次观察并按里程碑更新进展。

交互客户端（mysql/hbase shell 等不会退出的程序）用 `--idle N`：raw.log 连续 N 秒没有新字节即返回，并附 idle_seconds 与 idle_hint。这只是输出静止的启发式提示，不是完成证明；发送下一段输入前必须读日志尾部确认提示符。网络重传或分页器都可能造成假静止，拿不准就再等一轮或改用客户端自己的批处理入口。

`evidence/pty/<session>/` 保存 request.json、status.json、原始 ANSI 字节 raw.log 和已发送输入。读取日志尾部了解状态，但不能只因出现 `$`、`>` 或旧提示符就判断完成。原始输出不可改写；日志渲染不会产生新的执行事实。

交互客户端确需继续输入时，先确认当前进程/提示，再把准确字节写入文件：

```bash
python3 <skill>/scripts/pty_session.py send /任务目录 lab1-query --file /任务目录/quit-input.txt
```

文件包含需要的换行或控制字节；只发当前客户端预期的响应，不往未退出客户端追加下一道题。单次响应最多 4096 字节；长脚本从文件执行，不走键盘通道。queued 只表示排队，必须读输出与退出状态核对。输入文件和日志不记录密码或密钥。

确认应终止本任务进程时使用 stop，再查看 status 的真实退出结果。stop 仅请求停止该会话进程组，不承担远端作业撤销；集群作业需额外查询其任务 ID。会话 ID 已存在时先检查，不覆盖日志或盲目重跑。

## 批处理、挂起与幂等

- 用客户端本身的批处理入口，先查实际版本和帮助。HBase 的非交互模式可传递命令退出状态，正常交互 shell 的退出状态不能充分反映每条命令结果；详见 [HBase Shell 官方说明](https://hbase.apache.org/docs/shell/)。
- MySQL、Hive/Beeline 等使用其实际版本支持的文件或执行语句参数，检查是否还停在交互提示、分页器或多行输入中，不硬套其他客户端的退出命令。
- 长输出先完整落盘或捕获，再截取日志查看。不要为只看前几行把正在执行的命令随意接到 head；管道提前关闭可能改变生产者行为，部分输出也不能证明执行完成。
- 网络报错或 RPC 超时后，先查表、行数、目标文件和作业状态再重试。插入、导入、建表和集群提交尤其要检查是否已生效，避免重跑污染数据。
- 指标不符时核对原始行数、重复键、导入次数、过滤和统计口径。保留真实结果与原因，不将预期值写成实测值。

## 锁屏与分级证据

锁屏、屏幕不可读、机器休眠和远程断线是不同状态。锁屏后可继续实际可用的 PTY/文件工作，GUI 相关任务暂停；不能自动解锁、绕过安全提示，也不能假定进程整夜保持运行。恢复后查看真实进程、日志和文件版本。

| 证据 | 能证明什么 | 不能替代什么 |
| --- | --- | --- |
| 原始 PTY 日志、退出状态、数据文件 | 实际输出与命令结果，可复算数据 | 桌面软件界面、屏幕状态、用户亲自操作 |
| 真实日志渲染图 | 将已捕获的终端输出排版展示，便于放入报告 | 屏幕截图；未出现于日志的执行过程 |
| 真实界面截图 | 拍摄时实际可见的软件界面与输出 | 画面之外的完整运行与未验证结论 |

渲染结束会话：

```bash
python3 <skill>/scripts/render_terminal.py /任务目录/evidence/pty/lab1-query --out-dir /任务目录/evidence/lab1-render --font /可用等宽字体.ttf
```

需要 pyte 和 Pillow，依赖不影响原始 PTY 捕获。优先已有环境；缺少时可使用正规包管理器的隔离环境，例如 `uv run --with pyte==0.8.2 --with pillow python ...`。按输出语言选择有对应字形的等宽字体，检查中文、宽字符和换行。渲染器默认按终端单元格重排并保留 SGR 配色（提示符、高亮，与真实终端一致），不复刻窗口装饰；加 `--monochrome` 可改为单色。两种模式的"非屏幕截图"标签与 provenance 清单完全相同，图注披露义务不变。原始 ANSI 字节保留。输出包含日志快照、会话记录、SHA-256、分页范围与可见的“非屏幕截图”标签；滚屏重放有长度上限，原始日志仍须保留。

图注和最终说明都披露使用了日志渲染。若题目明确要求终端窗口/软件截图，登记待补拍的 requirement 或 blocking issue，保持相关 check 未通过；用户允许替代时记录授权范围，但不能声称教师已接受。可保留会话或重开日志查看；重开日志的截图也只是日志查看，不能伪称当时执行画面。

实现依据：[Python PTY](https://docs.python.org/3/library/pty.html)、[pyte 终端重放](https://pyte.readthedocs.io/en/latest/api.html)。
