# 按要求选择执行方式

混合作业按小问组合以下方法。先使用用户材料和课程约定，需要外部事实时查可核实来源，不伪造引文。

| 任务 | 执行重点 | 有意义的核验 |
| --- | --- | --- |
| 选择、填空、简答 | 按原题号回答，保留依据与必要推理，提交内容遵循题目要求。 | 覆盖小问，回看易混条件与单位；重复同一句回答不是核验。 |
| 数学、证明 | 明确定义域、条件和推导，按课程允许方法解答。 | 代回、边界、单位和反例搜索辅助检查；数值例子不能单独证明一般命题。 |
| 阅读、写作、翻译 | 对照题意与字数组织内容，保留术语、语气和逻辑。 | 事实、引文、任务覆盖、语义一致性，再查文风。 |
| 编程、SQL | 识别接口、版本、依赖、输入输出与禁止项，在真实环境运行；需要界面过程证据时用 CU 操作。 | 运行代表性及边界输入并核对输出；SQL 检查数据变化与查询结果。编译成功不等于全部正确。 |
| 数据分析、表格 | 识别单位、缺失值、分组和统计口径，从原始数据计算并生成图表和解释。 | 独立复算关键指标；公式需计算引擎重算，保存文件不代表计算完成。 |
| 实验报告、软件操作 | 先执行实验或软件任务，记录输入、参数、观察、实际错误，再填模板和截图。 | 输入、结果、软件画面与结论一致，每项操作要求有证据。 |
| PPT、图表、课程项目 | 保留指定版式、页数、尺寸、组件和可编辑源文件要求，实际生成和打开作品。 | 查看或播放最终输出，核对布局、图文关系和要求的功能。 |

## 依赖与阻塞

先产出真实数据、代码结果或图形，再写分析和结论。终端执行与锁屏取证见 [终端与证据](terminal-evidence.md)，软件/配置损坏见 [环境恢复](environment-recovery.md)，学校报告模板填充见 [报告构建](report-template.md)。失败时记录真实报错与环境，调整后重跑受影响部分。没有遇到的错误不写成“我调试时发现”。

缺少真实测量值时，可完成计算方法、表格结构等独立部分。只有题目要求模拟或用户接受模拟时才生成模拟数据，并标明性质；不能冒充真实测量。

要求操作某款软件时，确认可用性并实际完成步骤。等效路径须满足要求；无法满足就记录尚缺步骤，不能用生成的“软件截图”代替。

## 证据

做题前确定什么结果才算完成。证据随执行产生，保留原始数据、运行日志、查询结果、导出和必要截图。截图按题号与用途命名，含足够的结果与上下文，避开无关个人信息。

最终只交用户和作业要求的材料。内部计划、状态 JSON、风格审阅与调试记录留在工作目录，不塞入作业正文；题目要求过程文件时再一并交付。
