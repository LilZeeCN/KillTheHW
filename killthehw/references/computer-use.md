# 电脑操作贯穿执行

CU 用于进入作业、操作指定软件、观察结果、导出与核验。先查看当前宿主的工具说明和可用应用，不假设固定 API。脚本不能自行调用只对宿主 Agent 暴露的 CU 工具。

命令行任务优先按 [终端与证据](terminal-evidence.md) 使用 PTY。锁屏时继续实际可用的终端与文件工作，暂停依赖界面的步骤；日志渲染必须披露来源，不能冒充截图。

## 控制入口

- 默认优先用户已配置的 Ego Lite。若 CU 没有 Ego 标签页入口，用原生应用 `com.citrolabs.ego.lite`；不可用时选择满足登录和任务要求的可用浏览器，说明实际入口。
- 目的工具、CLI 或 API 可用于稳定的数据读写和批处理；需要界面步骤、目标软件特性或操作证据时用 CU。DOM/可访问性入口不能反映目标时依据截图操作。
- 保留当前任务的应用、文档、页面与目录。实际查看登录态，不能因曾导入过浏览器状态就断言已登录。
- 一个桌面同时只有一个控制者。其他并行工作只能处理独立文件或计算；用户正在操作时让出输入，恢复前重新观察。

## 观察、操作、核对

1. 观察应用、窗口、文档/URL、当前控件或截图，确认对象属于本次任务。
2. 基于刚读到的界面选择目标。索引、定位器与坐标来自当前观察；界面改变后不沿用旧索引。
3. 执行一小组顺序确定的动作。遇到弹窗、导航、异步任务、上传或提交边界时先等实际状态再决定；不写长串盲点流程。
4. 核对字段是否保存、运算是否结束、图是否生成、文件是否导出、平台是否接受。点击成功不等于业务成功。
5. 保留关键输入、实际观察、输出与必要截图；按完成小问、失败恢复等里程碑批量登记。重要状态变化立即记录。

优先工具自身的等待或状态查询。确有加载需要时短暂等待；不以固定长延迟代替核验。无法观察的步骤记为未核验。

地址、文件路径和提交字段的输入要核对实际显示值，不能只相信 paste、setValue 或 typeText 的返回。原生文件对话框出现后先观察再输入；路径建议出现不等于文件已选中，回到页面后还须核对附件名。输入异常时换有依据的输入方法，仍无法确认则保留阻塞，不误选相邻或历史文件。

## 失败与恢复

- 目标消失或点击无效：重新观察焦点、窗口、页面和弹窗，再定位重试。
- 找不到导出文件：查看软件状态和实际目录，不能因输入过文件名就报告生成成功。
- 上传或提交后超时：先看作业状态、历史和回执。结果未知写 submission_unknown，不盲目再次提交或撤回。
- 同一问题没有新证据又出现时，停止重复该动作；改用有依据的路径或提出具体阻塞。
- 登录、验证码和宿主审批按实际工具要求处理，只暂停依赖它的部分；不绕过权限或代替用户确认设备安全提示。

恢复记录说明当前实际停在哪里、什么已验证、什么未知，而非仅列准备执行的动作。

## 文件与平台

原件另存工作副本。保留指定可编辑文件和导出格式，确认打开的是最新版本。导出后用软件或渲染检查内容、公式、字体、截图与页数。

截图来自真实界面。可为可读性裁掉无关区域，但不拼接或替换结果伪造成功。含不宜交付信息时优先调整视图重新截图。

从会话确认课程/作业、平台和终点是读取、填写、上传还是提交。已有完整授权直接继续；确需新外部操作授权时先完成可审阅的答案和文件，再只询问缺失授权。

提交前核对作业名、附件列表、文件版本和必填字段；提交后查看回执、提交时间或历史。附件上传成功不能当作作业提交成功。
