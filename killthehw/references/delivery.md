# 核验与交付

核对原题与评分要求，覆盖小问、选做数量、字数、格式、引用、命名、附件和过程证据。按 [任务执行](task-execution.md) 选择核验；普通可逆编辑不额外搭建测试工程。

## 实际核验

- 文档/PDF：打开最终版本，检查公式、表格、图片、分页、字体和占位内容。正式成品覆盖每页；修改后重看受影响页和相邻分页，保存有用核验依据。
- 表格：核对公式、数据范围、单位、图表与计算结果；重算保存，查看关键单元格实际显示值。
- 代码/数据库：真实运行，验证输入输出、边界及持久化；记录环境、操作、退出状态与结果，语法检查不等于功能验证。
- 网页/演示/交互作品：在目标环境打开并操作，检查渲染与要求的交互，构建成功不能代替实际使用。
- 在线答题：核对题目对应关系与填写值；恢复后检查实际保存状态。

checks 记录方法、结果、对应文件散列值与可复核证据。一个核验可覆盖多项要求，但要明确对应关系。content/execution/calculation/visual 按用途选；style 或 existence 不能单独表示作业核验完成。

不强制所有题目使用全部检查种类。文档通常需 content 与 visual，程序需 execution，统计表需 calculation，并按版式要求增加 visual。

## 记录检查

运行 check_deliverables.py，检查输入版本和阅读记录、要求覆盖和任务状态、文件版本和核验依据、未解决阻塞及平台回执。

退出码 0 只表示记录一致，语义和 UI 真实性由实际工作证明。纯在线答题没有本地成品时，checks.subjects 可为空，但仍保存题目对应和平台观察证据；回执 deliverable_ids 可为空。

## 用户指定终点

- local：本地文件与核验完成后设 local_ready，返回文件链接。
- upload：在指定位置查看实际附件或草稿状态，设 uploaded，保存回执。
- submit：查看指定作业的提交状态或历史，设 submitted，保存回执。已有明确授权不重复询问。

外部目标须填 destination、scope 和 receipts。回执 destination 与目标一致，覆盖全部交付物。以真实页面判断，不能自行生成一段“已提交”充当回执。

未知状态写 submission_unknown，说明需要查证的页面或记录。仍可交付已完成的本地文件，但不能声称已达到提交终点。

最后给出文件、完成范围、实际检查和未完成内容。内部账本不默认作为作业成品。清理无用临时转换，保留原件、成品和有用证据；若清理了 checks 引用的证据，先以实际保留的核验记录替换对应引用。
